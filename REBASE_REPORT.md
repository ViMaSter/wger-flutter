## Intentional Behavior Changes

Upstream now owns the rest countdown: per timer page `timerStartedAt` in the gym
state, persisted across page rebuilds and app restarts, with `extendRest`,
"up next" and a background notification at the end of the rest. The fork's
separate `GymRestTimer` clock was removed so the two cannot disagree. The fork
features are rebuilt on upstream's state:

- `-15s`/`+15s` use `extendRest`; reset to min/max uses the new
  `GymStateNotifier.resetRest`. Min is the set's rest time (user countdown as
  fallback), max is the set's max rest time, disabled when absent.
- `+15s` is now also allowed after the rest ended (restarts from now, as in
  upstream's notification "+30 s"); `-15s` is disabled once the rest is over.
- `GymRestTimer` is now a follower of the gym state (`gymRestTimerProvider`,
  read when gym mode opens). It syncs the rest end to the watch and plays the
  fork's vibration pattern once at the end, also while on another page.
- The in-app alert only fires in the foreground; in the background upstream's
  notification alerts. Upstream's in-widget `HapticFeedback` alert was replaced
  by this service, so there is a single alert path.
- A rest that is already over when gym mode opens (restored workout) does not
  alert, matching upstream's "don't alert again when returning".
